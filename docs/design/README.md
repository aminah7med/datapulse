# التصميم المعماري

## المبادئ

1. تقسيم الحزمة حسب مسؤوليات المجال مع حدود واضحة بين الاستيعاب والتحقق والتحويل والجودة والحوادث والتخزين.
2. إبقاء التنسيق في Airflow، ومنطق المجال في `src/datapulse/`.
3. عزل تفاصيل البنية التحتية خلف حدود التخزين والإعدادات.
4. التوسع بإضافة موصلات أو قواعد ضمن المكوّن المناسب بدل إنشاء طبقات متداخلة بلا حاجة.

## مسار البيانات المقترح

`مصدر البيانات → ingestion → validation → transformation → quality → storage`

يمكن لـ `incidents` استهلاك نتائج الجودة لتسجيل الانحرافات وإدارتها. ينسّق Airflow هذا المسار، بينما تبقى تفاصيل السياسة والتنفيذ داخل الحزمة.

هذا المسار توجيهي فقط، ويحتاج إلى مراجعة عند اعتماد عقود البيانات ومتطلبات التشغيل الفعلية.
